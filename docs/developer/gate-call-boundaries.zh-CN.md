# Gate 调用边界与原生标量调用闭包

这次修复放在 Chimera 编译插件、离线分析和启动校验中。新的应用构建保留原有手写 RVV 和 tiled FlashAttention，只使用历史两项 RVV 兼容补丁，不再应用新增的 noinline/关闭 tiled 路径补丁或 Q8_K volatile 清零补丁。旧补丁及其测试结果作为历史证据保留。

## 编译插件

`GateRvvBoundaryPass` 在内联前遍历 Gate 根可达的直接调用，继续向实际携带可伸缩 RVV 值、分配或向量寄存器 clobber 的定义传递 Gate 禁自动向量化约束。内联约束单独决定。对能到达未解析间接调用的控制路径，沿标量包装函数找到首次引入显式 RVV 状态的调用，只在使用标量接口的调用点加 `noinline`。标量包装函数仍能内联，并带着受保护的调用点进入调用者。已经在参数或返回值中传递可伸缩向量的调用无法用这条规则隔离向量状态，仍由最终 ELF 检查判定。

同一个 RVV 函数可在纯计算调用点内联，同时在包含回调的控制路径保持调用边界。保留函数身份、链接属性与源码内联属性。旧规则曾把 Q3_K 矩阵乘内层的两个解包函数拆成调用，导致反复保存和恢复向量寄存器。控制路径仍需在最终 ELF 上验证，包括 `out_prod` 的量化回调和未解析的外部边界。该编译规则只负责缩小内联的影响范围，准入仍以严格检查为准。

`GateLocalMemsetPass` 在最后一个 IR 优化阶段展开 gated 函数的 LLVM memset intrinsic，避免后端将其降为外部 memset 调用时留下跨调用的显式 RVV 状态。展开为字节循环，保留 volatile、调试位置和适用的别名元数据，零长度不访问目标地址。真正的外部 memset 调用和未 gated 的函数不变。手写 RVV、算术及后端原有 gate/census 决策保持原义。

## 原生调用闭包

宽度值或宽度选择的控制流跨越原生数学函数调用时，调用者仍然 unsafe。新增证明只关闭“该原生调用可能回调应用”的外部边界，不清除向量对象、栈帧、宽度数据或 CFG 活性。

证明针对实际选定的 RV64 LP64D ELF 字节，不按库名或函数名豁免。它验证唯一动态符号及版本、PLT/GOT、精确函数范围、连续指令字节、所有可达普通及尾调用、返回地址、SP 和 ABI callee-saved 寄存器。只有私有栈帧和已重绑定的 TLS 对象允许写入。不可变数据的相等加载可用于分支证明；不把加载器初始化的 RELRO 数据当成 ELF 初值。

间接调用、应用回调、IFUNC、符号劫持、向量/CSR/系统指令、未知写入、缺失字节、递归或预算不足均保留开放边界。单根最多 64 个函数、128 KiB 代码，每个函数最多 4096 字节；另有有界数据流和时间预算。未证明的调用继续接受原有严格检查，不转换为成功。

证明以 `chimera-external-call-contracts-v3` 随 Workspace 保存。检查凭证版本升至 34，另以 `check_input_fingerprint` 绑定实际选择的模块集合、路径、字节 SHA、标量选择和交付方式。检查前后身份必须一致；替换或增加依赖、缺少输入绑定的旧凭证均须重新 check-elf，`--allow-problematic` 也不能越过此检查。prepare 会重新分析其实际选择的模块，不复用先前分析实例中的原生调用证明；未能重新证明的边界恢复开放状态及原有 unsafe 传播。

注册和运行时重新绑定模块 SHA、根导入、提供者定义、调用图代码 SHA、对象/TLS 重定位，并检查实际加载的 Runtime ELF 是否引入符号劫持。LD_PRELOAD、LD_AUDIT、LD_PROFILE 和系统 preload 仍被拒绝。

## 验证范围

测试逐字比较无 memset 的变换前后优化 IR，覆盖手写 RVV、控制包装、间接目标简化、函数指针身份及内联；执行 intrinsic 与真实调用的区分、volatile、零长度和带保护区的内存结果，并检查 32 位长度在 64 位地址上的无符号偏移扩展；另覆盖真实 ELF 符号/版本/PLT 绑定、回调、错误 ABI 返回、部分寄存器保存、可变与不可变加载、预算、Workspace 启动重绑和篡改拒绝。替换依赖的测试同时覆盖重新分析与旧证明的启动拒绝，单独更新 Manifest 哈希也不能使旧证明继续生效。

编译器和离线测试通过不等于完整模型迁移通过。候选工具链、未加迁移补丁的应用构建、严格检查、prepare、原生参考与真实自动迁移结果须分别记录；数值判据仍采用用户已授权的相对 PPL 2%，不宣称旧数值差异已经修复。
