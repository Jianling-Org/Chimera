# 标量硬件宽度缓存的活跃性

当前安全检查版本为 **32**。本维度跟踪仍活跃的本地宽度缓存，并保护由这些值选定的 CFG 路径；它不证明任意向量算法的数值正确性。普通地址／mask 选择影响及已确认的非栈缓存写出属于 warning；finding 仍只出现在实际 unsafe 的未覆盖调用边界。

真实反例来自旧 llama.cpp decode：

    csrr a2,vlenb
    srli s4,a2,1
    ...                 # a2 可被覆盖，s4 副本尚未结束
    jal  ra,callee
    ...                 # 继续用旧 s4 推进计数

现场旧步长 64 与迁移后的向量长度 16 混用，使 512 个非零标志只计出 128。保留反汇编夹具用于回归；这不表示当前重编 ELF 仍有该源头，也不能排除其他数值问题。

## 本地缓存的范围

来源包括非零目标的 vsetvli、vsetivli、vsetvl，以及 CSR vlenb、vl、vtype 的读取，包含已支持的数字别名。目标为 zero 不产生标量副本。已证明受目标最小 VLEN 支持、且常量 AVL 不超过最小 VLMAX 的结果可排除；可选 VTYPE 的容量计算本身不是支持证明。

每个有来源的函数运行一次前向来源分析与后向活跃性分析，两者相交得到 live_vlen_scalar_data：

- 直接复制、整数／浮点位搬运及纯宽度换算保留来源，例如 vlenb 右移一位、VL 乘常量元素大小。
- 普通输入与宽度共同参与的进度计算不产生新的宽度缓存，例如 s3 += VL。原 VL 副本是否仍活跃单独判定。
- a2 → v8 → s4 保留实际内容来源。覆盖 a2 不会消除 v8 或 s4；完整覆盖或死亡只结束对应副本。
- 已证明属于当前分配帧的 spill/reload 接入局部生命周期。固定槽按字节处理；可证明的 VLEN 符号区间复用现有栈对象及地址表达式。
- 整段独立覆盖和已证明的帧收回可以结束副本。部分写、mask、条件写、RMW、寄存器组别名及显式 vstart 的未覆盖前缀不能错误解除。
- SP 仍是调用／返回的实际隐式输入。宽度依赖的分配、准备及恢复继续由既有栈帧分析处理；本维度不替代该分析。

已识别的实际宽度缓存不受 assume-scalar-independent 的 UNKNOWN 栈尺寸范围假设排除。无来源函数不分配本维度的前后向状态图。

## 输入、状态与求解

输入为函数 CFG、目标 `scalar_width_facts`、前后标量表达式、RVV 配置、栈访问事实，以及全程序已确认的内部 ABI 转移站点集合。缺少必需语义能力是错误，不能解释为“没有宽度来源”。

前向状态分别记录实际内容和选择影响：标量寄存器集合、向量寄存器集合、固定帧字节集合、符号区间槽，以及相应的选择集合和未闭合效果 `escaped`。前向汇合使用可能性并集，迭代传播来源；后向根据实际 use/def 求活跃性固定点。输出标记取“可能含宽度的内容”与“后续仍需读取”的交集，并保留未闭合效果状态。

```text
有来源且被后续实际读取 → live_vlen_scalar_data
来源已经覆盖或死亡     → 结束相应本地副本
只有选择影响           → 诊断 warning
真实内容的效果无法建模 → 保留具体缺口及保守状态
```

没有任何宽度来源的函数走快速路径，不保留本维度的逐指令来源图或活跃图。前向更新默认预算为 `max(256, 64 × 指令数)`；耗尽时生命周期未被证明，整个函数保留标记并报告预算 warning，而不使用部分结果宣布死亡。

## 私有 spill、覆盖与向量中转

实际内容可沿 `a2 → v8 → s4` 流动。覆盖 a2 不会消除 v8 或 s4；每个副本独立终止。向量寄存器组必须完整且有效覆盖，才能清除对应来源。部分 lane、mask、条件写、读改写和组别名不能被当作完整覆盖；显式 `vstart` 存在未证明的重启前缀时，也不能依赖整段覆盖解除来源。

私有 spill 要求证明访问位于当前已分配帧的范围内。仅仅表达式含入口 SP 不足以证明私有。固定槽按字节记录，符号 VLEN 区间复用栈对象和地址表达式；reload 从已知或可能别名的私有槽取回内容。独立的完整覆盖和已证明的帧收回可以结束对应槽：

```asm
addi sp,sp,-64
csrr t0,vlenb
sd   t0,8(sp)      # 当前已分配帧中的私有宽度槽
li   t0,0
jal  ra,worker    # 后续 reload 保留槽的生命期
ld   s4,8(sp)
add  t1,s4,zero
addi sp,sp,64
ret
```

内存写的内容、地址／索引和执行条件分别判断：

| 情况 | 处理 |
|---|---|
| 实际宽度内容写入已证明私有帧 | 接入本地槽生命期 |
| 实际宽度内容写入已证明非栈地址 | `unsupported-nonstack-width-data` warning；不把后续所有点永久钉为 unsafe |
| 只有地址、mask 或条件依赖宽度 | 选择影响 warning |
| 实际宽度内容写出，位置或私有范围无法证明 | 保存地址／范围缺口及保守效果状态 |

`memory_private=false` 只表示私有性未被证明，不能据此推断已确认非栈。普通参数内存 load 不是宽度来源；随 VL 改变的分块长度、步长或地址也不等于写出了持久宽度缓存。

## 选择影响只报告 warning

宽度参与分支条件、地址／索引、mask，可能选择执行路径或普通数据，但不等于所选数据保存了宽度位。例如：

    vsetvli a4,a0,e32,m1,ta,ma
    addw    s3,s3,a4           # 普通进度累计，不产生新的宽度缓存
    ld      s4,0(s3)           # 地址被选择，不证明内容是宽度

选择状态用于诊断，不能单独新增 unsafe、seed、gate 源头或 finding。控制影响没有从报告中删除；受控写、受控调用、选址及 mask 的证据仍可供人工审查。普通参数内存加载本身不是宽度来源；只对已知本地 spill 的实际或可能别名保留缓存内容来源。

这是一项明确的工程范围选择，不是“选择影响已证明与程序数值无关”。它不改变既有动态栈尺寸证明器对控制条件的规则。

## 宽度条件选择的控制区域

已知 `vlenb`／`vl`／`vtype` 副本或受支持的宽度换算值若进入条件分支，分支及其控制区域使用独立的 `local-vlen-control` 来源标记为 unsafe。该来源记录分支地址和本函数检测到的宽度来源地址，不伪装成仍活跃的标量副本。

分支寄存器随后被覆盖，不会提前解除已选择路径的保护；有可靠共同汇合点时，保护在汇合后结束。嵌套分支和循环按 CFG 控制依赖处理。若控制区域不能可靠闭合，则报告 `unclosed-vlen-control-region` warning，并把该分支可达的代码保守标为 unsafe。无宽度来源的普通内存读取、常量条件和已证明独立的固定 VL 来源不会单独创建该标记。

该规则保护执行路径本身：路径内确定的内部调用沿现有传播继续；只有路径内存在未解析调用或未闭合外部边界时才可能产生 finding。普通向量访存的地址、mask 或长度随宽度改变，仍只是选择／效果观察，不能单独证明持久宽度缓存。

## 函数调用与值传播的边界

本维度采用标准 ABI 的局部寄存器生命周期，不跨函数推导参数、返回值或任意内存值：

- 普通 RA 链接调用结束 caller-volatile GPR／FP 和向量寄存器的局部缓存周期。不因某个实参寄存器含宽度，就把参数值传播到被调函数；也不凭返回寄存器名称制造缓存。
- 调用前后的真实间接目标及 SP 保留实际 use。callee-saved 副本、后续仍会 reload 的私有 spill 继续按本地活跃性跨调用保留。
- 正常返回读取 ra／SP，不隐式读取 a0/a1/fa0/fa1 作为潜在返回值。特别是 void 函数不会因此出现虚构的缓存传递。
- 自定义链接约定、未建模指令或未解析的非返回转移若涉及实际宽度内容，保留具体缺口；只有选择影响时不制造永久 escaped 标记。

完整解析到当前程序内部函数体的普通 ABI 调用／尾转移，不因“位于函数末尾、没有后继”就人为读取全部残留宽度副本。实际间接目标、SP 和调用后续指令的读取仍参与活跃性；真正跨正常调用活跃的副本继续保留。没有后续本地读取的死副本不会仅凭寄存器尚未覆盖而成为 seed。这项规则只使用现有目标解析结果，不要求额外证明被调函数的值效果或不返回属性，也不将被调函数认证为安全。

缺少整个程序的目标证据、目标集合为空、不完整、混有外部／PLT 目标，或使用非标准链接约定时，仍保留原转移守卫。已继承的 unsafe 上下文、向量／栈数据和动态栈帧分析不因本地死缓存结束而清除。未建模的末尾指令也不能被当作正常出口。

局部值传播与 unsafe 上下文传播不同。若真实 s4 副本跨一个完整解析的内部调用仍活跃，现有 seed／继承机制将被调函数体标为 unsafe，并继续沿调用图传播；不需要先证明被调函数的寄存器效果。纯继承宿主不能替代原源头。

OriginProver 的有限纯标量叶函数效果 API 保留为独立能力及回归测试，本缓存分析不再请求它。其 64 条上限不会阻塞本维度收敛。既有栈尺寸、返回值独立性及内存写证明仍保持原规则，版本为 origins-v16。

## 内存写出的分类

存储内容、地址／索引与执行条件分别记录：

| 证据 | 本维度行为 |
|---|---|
| 实际宽度内容写入可追踪私有帧 | 接入局部生命周期，不永久逃逸 |
| 实际宽度内容写入已证明的非栈地址 | warning，标为超出支持的缓存存储范围；不钉住后续 unsafe |
| 仅地址、mask 或 guard 依赖宽度 | 选择影响 warning，不当作持久宽度内容 |
| 实际宽度内容写出，但位置／私有范围无法证明 | 保留具体地址／范围缺口和保守状态，不能冒充已确认非栈写出 |

memory_private=false 不证明访问是非栈访问。普通分块访存的长度、步长或地址随 VL 改变，不足以证明写出了持久宽度缓存。不引入函数名豁免或泛化的向量数值等价证明。

## finding、报告与 gate

实际宽度活跃状态与原向量／栈数据、栈帧状态合并。finding 仅来自实际 unsafe 的未解析／不完整间接转移或未覆盖 PLT／外部边界。完整内部目标继续传播；正常返回和普通 store 不是调用边界。已绑定的外部标量叶凭据继续按既有契约闭合对应外部边界，不把调用者当前点改成 safe。

主检查 JSON 与继承报告均将本维度的观察写入 warnings[]，包含 severity=warning、actionable=false、地址及结构化来源。沿用 escaping-vlen-scalar-value 诊断编码以兼容旧消费者；**该编码在 v30 不再是 finding 或 gate 入选条件**。

真实边界的 activity_origins[].width_evidence 可附本地调用快照，区分当前 may 来源、实际活跃标量／向量副本、私有字节区间、内容、地址、mask 与控制。调用快照的 call_effect.status=not-requested，不额外解析或证明被调函数。prior_unclosed_effect=true 表示更早的实际效果缺口，不能读成当前仍有寄存器副本。

来源快照使用 chimera-width-obligation-v1；片段和符号槽最多展示 64 项，表达式限制为 64 节点、16 层及 512 字符，保留总量和 truncated。缺字段只表示没有该诊断，不能证明来源不存在。

来源审计仅为实际本地宽度标记建立 scalar-width-cache 候选；死来源、warning、普通 store／return 不制造受影响边界。旧 scalar_width_escape 计数字段兼容保留为 0。候选名单不代表 gate 已消除源头，仍需重编产物严格复检。

版本 31 及更早的成功凭证不能用于版本 32。严格检查必须实际执行且 findings 为 0；迁移数值正确性须另行通过同模型、输入、线程数及迁移条件的 PPL 对照。告警减少或静态通过不能代替数值验收。

## 运行时验证

宽度分析的静态通过不等于数值或迁移正确。使用相同最终ELF、模型、输入与参数建立原生对照结果，再执行当前Workspace的迁移测试，关联已完成迁移和实际执行状态。容差必须预先声明，不能把历史输入的阈值套到另一轮。

普通运行耗时不等于纯translated body算子开销；安全点允许线程回到目标original继续执行。条件Profile与外部scalar-leaf契约在数值对照通过后仍保持条件性。旧Workspace不会因升级分析器自动得到新安全表和补丁，需要重新严格检查、prepare和verify。当前配对验收的实际结果单独记录。
