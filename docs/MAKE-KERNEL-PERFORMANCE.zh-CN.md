## 对照设计

| 组别 | CPU | make 并行度 | 迁移策略 |
| --- | --- | --- | --- |
| X100 基线 | 0–7 | `-j8` | 固定组，关闭自动迁移 |
| 异构实验 | 0–15 | `-j16` | bootstrap 继承策略，注册工具链完成就绪后自动迁移 |

两组使用同一重编 make、同一内核源码快照、同一配置和编译工具链。关闭 ccache，固定构建时间戳、用户、主机和版本信息，控制增量构建、缓存、温度及频率影响。8 核组普通运行，不加载 bootstrap 或注册表；16 核组加载 bootstrap 并承担自动迁移的全部开销。

先进行小型编译链预检，再各完成一次干净的 Image 构建。首次两次构建只形成初步加速比；若资源和时间允许，交替顺序复测并报告中位数及波动。构建模块不是默认计时范围，不能混入其中一组。

鉴于磁盘空间，拟评估关闭 DWARF/BTF 的共同配置。只有确认依赖、空间与配置一致后才执行。采用顺序构建，保留各组最终 Image、配置、日志、哈希与统计；只清理本实验自己的中间产物，禁止清理已有测试内核或历史诊断文件。

## 正确性准入

1. 翻译器及 bootstrap 回归通过，保留失败日志。
2. 识别实际执行链：make、shell、gcc、cc1、汇编器、链接器及辅助程序。需要跨组迁移的程序必须通过保守检查并生成匹配原生依赖的 Workspace；不使用 `--allow-problematic`。未注册编译器可以在来源组内执行，但必须验证其未就绪状态和 CPU 组约束。
3. 不能把 `-j16` 等同于 16 核。采样实际进程 CPU、每核负载和内核迁移计数；若编译任务仍限制在单组，实验无效。
4. 小型 C 编译产物跨组一致并正确运行，再开始完整构建。
5. 两组构建退出码为零，检查 Image/vmlinux 格式和配置、比较可复现产物 SHA-256。若不同，定位差异后再判断正确性，不能仅凭 make 返回成功认定通过。
6. 每组退出后账本、pending 和 CPU reservation 全部归零，无超时或新增内核告警；保存 dmesg。

未注册的 gcc/cc1 等 exec 会保持未就绪。如果 make 的迁移使不同时刻创建的子任务分布到两组，也可能形成异构并行；必须用采样证明，且不能声称编译器本身迁移成功。若始终只有一组执行编译任务，不能将结果作为 16 核实验。

## 测量与报告

记录墙钟时间、user/system 时间、峰值内存、退出码、每核利用率、温度/频率、迁移增量和清理统计。两组使用一致的计时边界，配置生成不计入完整编译时间。

- 加速比：`S = T_X100_8 / T_16`。
- 相同工作量吞吐提升：`(S - 1) × 100%`。
- 耗时缩短：`(1 - T_16 / T_X100_8) × 100%`。
- 相对核数效率：`S / 2`。由于 A100 与 X100 不同构，此指标只作为相对核数参考，不能解释成同构 CPU 扩展效率。

在工具链准入和首轮构建完成前，不给出未经测量的加速比。预检耗时取决于 gcc/cc1 安全分析；完整构建 ETA 以首轮日志进度修正。
