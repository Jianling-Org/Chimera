# 迁移安全边界

本实现依赖可信的配对内核、BPF环境、编译器/译器、运行时和应用输入。Workspace的哈希和ABI校验用于验证内容与离线输入一致；哈希本身不证明发布者身份，也不提供对任意恶意ELF的沙箱。

内核控制接口和BPF装载涉及目标机权限；应用注册与迁移只应使用经过核对的Workspace和接口。全局map对象、生命周期、队列与目标注册必须符合配对内核约定，不能用同名但不同对象的map替换既有绑定。

已验证的迁移路径需要精确地址映射、足够安全元数据和可恢复源上下文。缺少路线/元数据、translated body内收到proposal、非零vstart等情况必须拒绝准备并保留源执行状态。未知trap仍失败关闭，不能把邻近地址或任意跳转当作已证明的安全点。

条件性安全分析依赖明确声明的范围与外部契约。改变ELF、依赖、工具链、Profile或ABI后需要重新验证；旧凭证和单次正常输出不能授权新组合。

运行结果检查包含数值对照、成功COMMIT ACK、完整状态链、逐TID CPU trace、账本清理及内核告警。本文定义工程边界，发布验收的实际环境和覆盖由对应验收摘要记录。
