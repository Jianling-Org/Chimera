# K3 GCC：16 并发编译进程 8 核到 16 核动态伸缩演示

之前的 [GCC 功能验收](../gcc-validation/k3-20261029/README.md) 和 [16 并发性能对照](../gcc-performance/k3-20261030/README.md) 已经通过，基准范围固定为 Chimera `578ab8321`、内核 `6.18.3-chimera-d02cd7352`、已准备好的 GCC / Workspace 以及 `assume-scalar-independent` 约束条件。

本演示脚本复用上述已验收工件，构建动态伸缩与在线迁移的端到端演示流程，不修改或覆盖历史验收记录。

> **注意**：本演示实际运行 16 个并发 `cc1` 编译进程（各主要使用 1 个工作线程），上级 `xgcc` 调度进程也会显示在系统进程树中，脚本不包含虚假的忙等待或伪造线程。

---

## 1. 运行环境与前提

- **执行机要求**：须在原 K3 板端环境下以 `root` 权限运行，脚本与 `run-demo.sh` 需位于同一目录；
- **依赖环境**：使用标准库 Python 即可，其余依赖项来自已验收工作目录，无法在普通的非 K3 Linux 主机上直接执行；
- **资源限制**：系统单元限制 12 GiB / 10 GiB high 内存水位、0 swap、15 分钟超时；启动前需确保至少 12 GiB `MemAvailable` 与 6 GiB 可用磁盘空间；
- **互斥检查**：启动时会检查后台任务，若 4.2 独立审计或其他 Chimera 关键任务正在运行，演示将拒绝启动以避免干扰。

### 终端 1：状态与 CPU 核心监控
先打开监控终端以直观观察进程分布：

### 终端 2：执行演示


## 3. 运行阶段与观测点

流程首先串行生成一个原生参考对象，输出 `PHASE1` 提示后正式进入 16 进程演示阶段：

1. **第一阶段（Phase 1：8 核受限运行）**：
   - 16 个 `cc1` 进程完成真实的 bootstrap 与 Runtime 初始化；
   - 进程被限制在 `AllowedCPUs=0-7`（X100 簇）内并行编译，默认保持 15 秒供观察。
2. **第二阶段（Phase 2：动态扩核与跨簇自动迁移）**：
   - 脚本将当前演示单元的 cpuset 动态扩展为 `0-15`（纳入 A100 簇）；
   - 在系统的 `prefer-x100` / 迁移调度策略作用下，原生编译进程在运行时捕获扩核信号，通过 Runtime ACK 完成物理跨 VLEN 状态转换与调度提交，平滑扩展分布到两个核心簇上；
   - **关键特征**：在此过程中**没有重启任何编译器进程**，也**没有使用人工外部命令强制迁移**，完全由 Chimera 运行时自动接管。
3. **第三阶段（结果检验与正确性校验）**：
   - 16 个编译任务正常退出（返回码 0）；
   - 编译产出的所有目标文件 SHA-256 校验和与原生参考逐字节一致；
   - 链接生成的二进制文件分别在静态 X100 和 A100 核心上执行，与独立 Python 整数参考模型比对，确保计算结果 100% 正确。

> **参数调整**：默认输入代码量为 6144 个函数。若机器编译速度过快导致未完整覆盖观察窗口，脚本会明确提示并中止，绝不打印伪造的 PASS。可通过参数扩大测试负载：
> ```bash
> bash /root/chimera-gcc-demo-tools-v1/run-demo.sh --functions 8192 --hold-seconds 20
> ```

## 4. PASS 判据与指标解释

本演示的成功（PASS）基于严格的形式化与多维运行时证据链：

1. **PID 连续性**：两个阶段必须观测到完全相同的 16 个 PID（同一批进程，无进程替身）；
2. **物理核心分布证据**：
   - Phase 1 阶段采样必须 100% 局限在 CPU 0–7 并有效覆盖全部 8 核；
   - Phase 2 阶段在放开 cpuset 后，采样周期内必须证实进程扩展覆盖 CPU 0–15 且两簇同时处于活跃工作状态；
3. **真实内核迁移证据**：
   - 必须记录到原 `cc1` 进程产生的成功 raw ACK 与内核跨簇物理提交记录；
   - 迁移方向计数与全局硬件事件增量精确一致（仅扩核而未触发真实迁移将被判定为 FAIL）；
4. **系统健康状态**：
   - 真实初始化见证与处理函数记录完整；
   - 9 项退出账本归零、0 超时、0 事件丢失；
   - 内核健康状态良好，退出钩子会自动清理本次演示的私有探针。
